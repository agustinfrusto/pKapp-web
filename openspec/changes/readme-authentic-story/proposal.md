## Why

El README actual está bien en contenido, pero está escrito con un tono demasiado de "producto" y demasiado lejano de la verdad del proyecto. La versión correcta del proyecto no es “un app launch”; es una herramienta útil que nació para una necesidad concreta, creció con uso real y luego ayudó a más personas a estudiar.

Necesitamos documentar esa historia con un tono más honesto, más claro y más fiel a la forma en que realmente se construyó pKapp.

## What Changes

- Se define una narrativa pública más auténtica para el README: “nació para ayudar a una persona y luego fue útil para otras”.
- Se incorpora el enfoque de Spec Driven Development como eje de la forma en que el proyecto se mantiene y evoluciona.
- Se fijan reglas de estilo documentales para no volver al tono promocional ni al lenguaje de producto.
- Se mantiene una estructura clara y consistente para futuras ediciones del README: introducción, utilidad real, enfoque de construcción, características, instalación, arquitectura, licencia.

## Capabilities

### New Capabilities

- `documentation-voice`: voz pública del proyecto orientada a la claridad, la honestidad y la utilidad, no al marketing.
- `readme-structure`: estructura estable del README para preservar consistencia en futuras ediciones.

### Modified Capabilities

Ninguna.

## Impact

- Es un cambio de documentación únicamente; no modifica lógica de negocio ni comportamiento del producto.
- Afecta la forma en que se comunica el proyecto a usuarios, colaboradores y personas que revisan el repositorio.
- El beneficio es mayor coherencia narrativa, mejor credibilidad y menos riesgo de que el README parezca un pitch comercial.
